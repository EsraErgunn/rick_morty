# Personal preferences (all projects)

## Communication
- Talk to me in Turkish. Keep explanations short and concrete; explain *why* when you make an architectural choice.
- Code, identifiers, code comments, commit messages and PR descriptions are in English.

## Git
- Commit messages in English, Conventional Commits (`feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `chore:`).
- Never push, force-push, or rewrite history unless I ask.

## Working style
- For anything touching 3+ files or architecture: show a short plan first and wait for my OK.
- Ask before adding a new dependency, and say why it is needed.
- Before saying "done": run the project's analyzer and tests and report the result honestly (including failures).
- If you are unsure about a requirement, ask instead of guessing.
- Never weaken a security control (secure storage, HTTPS, rules, obfuscation) to fix an error.
